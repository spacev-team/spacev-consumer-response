# 발송 전 검수표

## 입력과 질문

- [ ] 공문 또는 민원 접수 내용, 결제 상세 정보, 계약메모 전체를 확인함
- [ ] 필요한 자료가 없거나 상태가 충돌하면 초안 전에 질문함
- [ ] 계약기간·이용상품 외 계약 항목을 추가했다면 사용자의 동의를 받음
- [ ] 계약기간과 이용상품은 결제 상세 또는 사용자 명시값을 원문 그대로 전사함
- [ ] 계약메모의 날짜·다른 계약명을 이용해 계약정보를 보정하지 않음

## 내용

- [ ] 1항은 기본적으로 계약기간·이용상품만 있음
- [ ] 결제 상세의 금액 구성을 쟁점과 무관하게 본문에 옮기지 않음
- [ ] `이용대금 ○원(임대료 ○원, 관리비 ○원, 청소비 ○원)` 식의 나열이 없음
- [ ] 2항은 민원인의 주장·요구와 핵심 경위만 있음
- [ ] 3항은 당사의 실제 중재·조치와 임대인의 확인된 입장, 역할 한계, 후속 지원을 담음
- [ ] 당사가 임대인과 실제 협의한 노력이 드러남
- [ ] 같은 사실이 2항과 3항 또는 문단 사이에서 두 번 나오지 않음
- [ ] 보증금은 민원 쟁점이 아닌 경우 본문에 없음
- [ ] 단순 증빙 공백을 굳이 본문에 쓰지 않음
- [ ] `회신일 현재 ~ 확인되지 않았습니다`처럼 불필요한 미확인 상태가 없음
- [ ] 조건부·가정적 환불 발언을 최종 입장처럼 쓰지 않음
- [ ] 전대·등록 권한 등 리스크 쟁점은 중립적인 사실확인 수준으로만 씀
- [ ] `CS`, `CS 지원금`, `CS 보상`, `지결완료` 같은 내부 용어가 없음
- [ ] 회사 보상은 `민원인의 불편을 고려하여 이용 수수료 ○원을 현금으로 보상`하는 식으로 자연스럽게 표현함
- [ ] `당사가 보관하고 있지 않습니다`, `임의로 회수`, `전액 반환을 확정할 수` 같은 딱딱한 방어 문장이 없음
- [ ] 새 환불·보상·책임 인정을 만들어내지 않음
- [ ] 금지 용어가 없음

## 형식 및 산출물

- [ ] 2항은 2~5개 짧은 문단
- [ ] 3항은 2~4개 짧은 문단이며 억지로 문단 수를 채우지 않음
- [ ] 각 문단이 렌더링 결과 3줄 이내
- [ ] 네이티브 Google Docs 기준 템플릿을 copy하여 만들었고 원본은 수정하지 않음
- [ ] 우측 상단 SpaceV 로고 positionedObject가 유지됨
- [ ] 계약 표가 기본 2행×2열이며 계약기간·이용상품만 있음
- [ ] 계약기간·이용상품이 잠근 원문 값과 문자 그대로 일치함
- [ ] 고정 양식의 빈 필드(수신인 `담당자님` 단독, 빈 계약기간/이용상품 등)가 필요한 곳에 남아 있지 않음
- [ ] 과거 사건 답변서의 이름·날짜·금액·문구를 템플릿 사실처럼 재사용하지 않음
- [ ] 문단·표·페이지 구조가 깨지지 않았고 불필요한 빈 문단/빈 페이지가 없음
- [ ] **DOCX/Word/PDF 파일을 만들지 않았음**
- [ ] **최종 결과는 네이티브 Google Docs URL임**

사용자에게는 아래 정도로만 요약한다.

```markdown
**발송 전 검수**
- 민원 쟁점과 직접 관련된 사실만 반영
- 당사 중재·조치와 역할 한계 구분
- 동일 사실 중복 없음
- 내부 용어/불필요한 미확인 상태/금액 세부 나열 제거
- SpaceV 로고 포함 Google Docs 양식 유지
```


## Native-copy fidelity requirement

Before this workflow starts, apply `native-copy-fidelity-gate.md`. Native file copy must succeed and the copied document must pass the structural clone signature before any response prose is drafted. A blank/recreated Google Doc is always a failure.
