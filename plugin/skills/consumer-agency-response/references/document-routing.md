# 문서 작업 경로

문서 복사 기능을 확인하기 **전에** 사용자가 요청한 작업을 판별한다. 이 파일은 경로 선택과 중단 사유의 단일 기준이다. 기본 프롬프트나 다른 참고 파일의 복사 안내는 `copy_master`에만 적용한다.

## 1. 사용자 요청으로 경로 선택

| 사용자 요청 | 경로 | 필요한 기능 | 편집 대상 |
| --- | --- | --- | --- |
| 특정 Google 문서를 지정하고 “직접 수정”, “이 문서에 채워줘”, “여기에 작성”, “원본에 반영” 등 요청 | `edit_existing` | 지정 문서 현재 내용 읽기 + 내용 편집 | 사용자가 지정한 동일 document ID |
| 새 답변서·사본 생성 요청 또는 수정 대상이 없는 일반 답변서 작성 요청 | `copy_master` | 마스터 읽기 + 네이티브 복사 + 사본 읽기·편집 | 이번에 생성한 사본 document ID |
| “채팅으로만”, “파일 필요 없음”, “이 문단은 챗으로 줘” 등 명시적인 텍스트 요청 | `text_only` | 제공 자료 판독 | 요청한 채팅 텍스트 |

문구 일치만으로 판정하지 말고 대화의 의도를 따른다. 명시적인 수정 대상과 직접 편집 요청이 있으면 `edit_existing`을 선택한다. 링크가 참고자료로만 제공된 경우에는 그 문서를 쓰기 대상으로 삼지 않는다. 참고 문서와 수정 문서가 함께 있어도 수정 대상이 명확하면 다시 묻지 않는다.

사용자의 명시적인 작성 방식은 이 스킬의 기본 작업 절차보다 우선한다. 이는 실제 문서 접근권한, 읽기 전용 정책, 보호된 문서 요소를 우회할 수 있다는 뜻이 아니다.

## 2. `edit_existing` — 지정 문서 직접 편집

1. 사용자 링크·문서 ID·연결 앱의 정확한 원본 매핑으로 수정 대상을 확정한다. 제목 검색으로 비슷한 문서를 대신 선택하지 않는다.
2. 연결된 Google Drive/Docs에서 **그 문서의 현재 내용**을 읽고 document ID, 탭, 개정 정보, 편집 범위, 로고·표·제목·발신부를 확인한다. 읽기 전용 첨부 스냅샷을 원본 대신 수정하지 않는다.
3. 사용할 수 있는 읽기·편집 동작을 확인한다. **copy/create 기능 유무는 이 경로의 조건이 아니다.** 고정 마스터를 추가로 열거나 복사할 필요도 없다.
4. [native-copy-fidelity-gate.md](native-copy-fidelity-gate.md)의 기존 문서 검수를 적용한 뒤, 같은 document ID의 빈 필드 또는 기존 사건 문구를 현재 사건 내용으로 채우거나 교체한다.
5. 기존 내용이 채워져 있어도 새 답변서 작성을 요청한 작업 문서라면 사건 값과 본문을 교체한다. 단순 문구 수정 요청이면 지정 범위만 수정한다. 다른 사건·다른 탭의 내용은 요청 범위 밖이면 유지한다.
6. 편집 후 같은 문서를 다시 읽어 내용과 양식을 검수하고 **같은 원본 링크**를 반환한다. 새 사본이나 로컬 파일을 대신 만들지 않는다.

사용자가 직접 수정을 이미 허용했다면 “복사 없이 수정해도 되나요?”라고 다시 묻지 않는다. “플러그인 규칙을 먼저 수정해야 한다”, “복사 기능이 없어서 작성할 수 없다”는 이유로 이 경로를 중단하지 않는다.

## 3. `copy_master` — 새 답변서 생성

1. [google-docs-template.md](google-docs-template.md)의 영구 마스터를 고정 ID로 읽는다. Drive에서 대체 템플릿을 검색하지 않는다.
2. 실제 호출 가능한 네이티브 파일 복사 동작을 확인하고 실행한다. 앱이 연결되어 있다는 사실만으로 복사 기능이 있다고 판단하지 않는다.
3. 사본 ID가 마스터와 다른지, 사본에 마스터의 양식이 보존되었는지 확인한다.
4. 사본의 기존 필드·본문만 채운 뒤 검수하고 사본 링크를 반환한다. 영구 마스터에는 사건 내용을 쓰지 않는다.

복사 기능이 없으면 준비된 작업 문서의 링크와 직접 편집 요청을 받아 `edit_existing`으로 이어갈 수 있다. 아직 지정·허용되지 않은 문서를 임의로 수정하거나 빈 문서에 양식을 재구성하지 않는다.

사용자가 영구 마스터 ID 자체를 사건 작성 대상으로 준 경우에는 작업용 사본이 필요함을 설명한다. 사용자가 마스터 양식 자체의 변경을 명시한 경우에는 사건 답변서 작성과 별도의 양식 편집 작업으로 취급한다.

## 4. 막힌 원인만 정확히 설명

- **읽기 실패:** 대상 문서의 현재 내용을 확인할 수 없다고 설명한다. 오래된 첨부 스냅샷으로 원본을 덮어쓰지 않는다.
- **편집 동작 미제공:** 현재 대화에서 문서를 편집하는 기능을 사용할 수 없다고 설명한다. 사용자에게 Drive 권한이 없다고 단정하지 않는다.
- **실제 접근 거부:** 도구가 반환한 접근권한 오류와 해당 문서를 구체적으로 안내한다. 다른 계정·다른 링크가 가능하다고 추정하지 않는다.
- **복사 동작 미제공:** `copy_master`에서만 새 문서 생성이 막힌 이유로 안내한다. 준비된 문서의 직접 편집은 별개임을 설명한다.
- **수정 대상 불명확:** 어느 문서를 수정할지 한 번만 확인한다. 이미 정확한 수정 대상이 지정되어 있으면 재확인하지 않는다.
- **필수 양식 누락:** 누락된 로고·표 등 실제 요소를 설명한다. 읽기·편집·복사 권한 문제로 바꿔 말하지 않는다.
- **편집 중 개정 충돌:** 문서를 다시 읽어 다른 사람의 변경을 보존하고 범위를 재확정한다. 오래된 인덱스나 강제 덮어쓰기로 진행하지 않는다.

중단 설명은 선택한 경로, 실제 실패한 동작, 다음에 필요한 최소 조치만 담는다. 공통의 “복사·편집 권한 또는 기능을 확인할 수 없어 중단” 문구로 서로 다른 원인을 묶지 않는다. 이미 일부 편집했다면 수정된 범위를 밝히고 전체 완료로 표시하지 않는다.

## 5. 공통 범위

- 기관 공문·결제 상세·계약메모의 사실 판독, 금액 구분, 승인되지 않은 환불 금지, 용어·문체 기준은 모든 경로에서 동일하다.
- Google Docs 결과를 요청했으면 완성 답변서를 채팅·Word·Markdown으로 대신 내보내지 않는다. `text_only`는 사용자가 선택한 별도 결과물이다.
- Google Docs 쓰기는 연결 앱의 정확한 원본 편집 동작으로 수행한다. 스냅샷 업로드·교체로 원본 편집을 대신하지 않는다.
- 새 문서 생성 시의 마스터 사본 검증과 기존 문서 편집 시의 전후 보존 검증을 혼동하지 않는다. 기존 문서에 대해 “이번 대화에서 사본을 만들었음”이나 “필드가 처음부터 비어 있음”을 요구하지 않는다.
