# 소비자기관 답변서

국내 소비자기관 민원에 대해 필요한 사실만 골라 담백하게 작성한다. 많이 받은 자료를 많이 쓰는 것이 목표가 아니다. `민원 쟁점 → 실제 경위 → 당사의 중재·조치 → 역할의 한계 → 후속 지원`이 한 번씩만 나오게 한다.

## 출력 하드스톱 — 가장 먼저 적용

이 Skill의 파일 결과물은 **네이티브 Google Docs 링크 하나**다.

- Word, DOCX, PDF, 로컬 문서 파일을 생성하지 않는다.
- Documents/DOCX 생성 기능을 중간 단계로도 사용하지 않는다.
- 반드시 Google Drive/Docs 앱으로 기준 Google Doc을 네이티브 복사한 뒤 복제본만 편집한다.
- Google Drive/Docs의 복사·편집 기능이 현재 세션에서 불가능하면 **다른 형식으로 우회하지 않는다.** `Google Drive에서 기준 문서를 복사·편집할 수 있는 권한/기능이 필요합니다.`라고 안내하고 중단한다.
- 최종 응답에 첨부파일을 만들지 말고 **검증된 Google Docs URL만 반환**한다.

## 시작 순서

1. [workflow.md](references/workflow.md)를 읽고 입력자료와 작성 전 확인 게이트를 적용한다.
2. 사건 쟁점에 필요한 부분만 [issue-guides.md](references/issue-guides.md)에서 읽는다.
3. 초안 전에 [writing-standard.md](references/writing-standard.md)의 관련성 필터와 중복 금지 규칙을 적용한다.
4. 좋은 사례의 구조와 금지 문장 회귀 예시는 [precedent-patterns.md](references/precedent-patterns.md)에서 참고한다.
5. 파일 생성 전 [qa-checklist.md](references/qa-checklist.md)를 확인한다.

## 입력자료

기본 입력은 세 가지다.

1. 소비자기관 공문 또는 민원 접수 내용
2. 결제 상세 정보
3. 계약메모 전체

사용자의 특별 요청은 선택사항이다. 세 자료 중 하나가 빠졌고 답변 방향에 영향을 주면 먼저 요청한다.

**결제 상세 정보의 기본 목적은 `1. 계약 내용`의 계약기간과 이용상품을 채우는 것이다.** 결제금액·임대료·관리비·청소비·보증금·수수료를 본문에 자동으로 옮기지 않는다. 금액이 민원 쟁점 자체일 때만 필요한 범위에서 사용한다.

### 계약정보 잠금(필수)

`계약기간`과 `이용상품`은 추론해서 작성하지 않는다. **결제 상세 정보 또는 사용자가 명시적으로 적어 준 계약 상세의 표기값을 그대로 복사한다.** 계약메모의 입·퇴실일, 상담 중 언급된 기간, 다른 계약의 상품명으로 대체하지 않는다.

- 결제 상세가 있으면 이를 최우선 원천으로 사용한다.
- 사용자가 계약기간·이용상품을 텍스트로 직접 지정했다면 그 값을 원천으로 사용할 수 있다.
- 여러 계약이 섞여 있거나 대상 계약이 불명확하면 문서를 만들지 말고 계약번호 또는 대상 계약을 확인한다.
- 날짜 형식, 괄호, 주수 표기, 상품명의 이모지·특수문자를 임의로 정규화하거나 보태지 않는다.
- 생성용 JSON에는 `contract_source`를 반드시 포함한다. `raw_excerpt`에는 실제로 읽은 계약기간과 이용상품이 들어 있는 원문 일부를 그대로 옮기고, 최종 `contract_period`와 `product_name`은 그 안에 문자 그대로 존재해야 한다.

```json
"contract_source": {
  "type": "payment_detail",
  "confirmed": true,
  "raw_excerpt": "계약기간\n2026-08-17 ~ 2026-08-30 (2주)\n이용상품\n특가 외대2분 풀옵"
}
```

## 작성 전 확인

자료를 먼저 읽고, 정말 필요한 질문만 한 번에 묶어 묻는다. 다음 경우에는 초안부터 만들지 않는다.

- 민원인의 최종 요구가 불명확함
- 임대인의 현재 입장 또는 실제 처리 상태가 충돌함
- 당사 조치가 `제안/예정/완료` 중 무엇인지 불명확함
- 계약기간 또는 이용상품을 확인할 수 없음
- 공문이 별도의 질의 항목에 답하도록 요구함
- 기본 계약 표에 계약기간·이용상품 외 항목을 넣어야 할 이유가 있음

추가 계약 항목이 필요하면 먼저 이렇게 제안한다.

> 이 사안은 ○○ 확인이 중요해서 △△ 항목도 넣으면 어떨까요?

사용자가 동의하기 전에는 추가하지 않는다.

## 고정 작성 원칙

- `1. 계약 내용`은 기본적으로 **계약기간, 이용상품 두 항목만** 쓴다.
- `2. 민원 내용 및 확인 결과`에는 민원과 직접 관련된 주장과 핵심 경위만 쓴다.
- `3. 민원 관련 당사 입장 및 조치`에는 당사가 실제로 한 연락·확인·협의·보상과 임대인의 확인된 입장, 당사 역할의 한계, 향후 중재를 쓴다.
- **같은 사실은 문서 전체에서 한 번만 쓴다.** 다른 섹션에서 표현을 바꿔 반복하지 않는다.
- 당사가 임대인에게 연락하고 협의를 시도한 과정은 보여준다. 단순히 `권한이 없다`는 문장으로 끝내지 않는다.
- 임대인이 전액 반환에 동의하지 않은 구체적 이유가 자료에 명확히 있으면 필요한 범위에서 쓴다. 이유가 없으면 만들지 않는다.
- 협의 중 나온 조건부·가정적 표현은 최종 합의나 실제 처리 결과가 아니면 본문에 굳이 노출하지 않는다.
- 보증금은 민원 쟁점이 아니면 본문에서 제외한다.
- 수리 완료 자료, 전대 권한 자료 등 **미확인 사실 자체를 설명하는 문장**은 답변에 꼭 필요한 경우가 아니면 제외한다. 대신 당사가 실제로 어떤 확인·조치를 요청했는지를 쓴다.
- `회신일 현재 ~ 확인되지 않았습니다`, `지급 완료 사실은 확인되지 않았습니다`처럼 **당사에 불리할 뿐 결론에 필요하지 않은 미확인·미완료 상태 문장**은 기관이 직접 묻지 않는 한 쓰지 않는다.
- 전대·등록 권한 등 리스크가 큰 내용은 위법 여부를 판단하거나 세부 미확인 자료를 열거하지 않는다. 필요하면 `민원인이 제기한 임대 권한 관련 내용에 대해서도 당사는 임대인에게 사실관계 확인을 요청하였습니다.` 정도로만 쓴다.
- 내부 처리 용어인 `CS`, `CS 지원금`, `CS 보상`을 외부 답변서에 쓰지 않는다.
- 회사가 지급한 금액은 실제 처리 성격을 외부 문장으로 풀어 쓴다. 권장: `민원인이 이용 과정에서 겪은 불편을 고려하여, 당사는 이용 수수료 40,590원을 현금으로 보상하였습니다.`
- 이용대금 반환이 쟁점이어도 `이용대금 410,000원(임대료 360,000원, 관리비 20,000원, 청소비 30,000원)`처럼 **총액과 세부 구성을 한 문장에 나열하지 않는다.** 금액 산정 자체가 쟁점인 경우에만 필요한 항목을 최소한으로 쓴다.
- 한 문단은 원칙적으로 1~2문장, 렌더링 결과 3줄 이내로 쓴다.
- 금지 용어: 숙소, 숙박, 플랫폼, 게스트, 호스트, 예약, 체크인, 체크아웃.

## 역할과 한계 — 부드럽게 설명

역할의 한계는 **당사가 무엇을 했는지 설명한 뒤**, 짧고 자연스럽게 쓴다.

권장:
> 해당 이용대금은 입주 확인 후 임대인에게 정산된 상태입니다. 이에 반환 여부는 임대인과의 협의를 통해 조정이 필요한 사항으로, 당사에서 직접 반환하기는 어렵습니다.

피함:
> 이용대금은 임대인에게 정산되어 당사가 보관하고 있지 않습니다. 당사는 임대인의 동의 없이 이를 임의로 회수하거나 민원인에게 직접 반환할 수 없습니다.

`당사 책임이 아닙니다`, `규정상 불가합니다`, `임의로 회수`처럼 방어적으로 들리는 표현을 중심 문장으로 쓰지 않는다.

## 결과물

- 사용자가 `채팅으로`, `텍스트로`, `파일 필요 없음`이라고 하면 채팅 텍스트만 제공한다.
- 그 외에는 **네이티브 Google Docs만 생성한다. DOCX/Word 파일을 만들지 않는다.**
- [google-docs-template.md](references/google-docs-template.md)의 기준 문서를 반드시 네이티브 Google Docs `copy` 기능으로 복제한 뒤 복제본만 편집한다.
- 기준 문서 원본을 직접 수정하거나, 빈 Google Doc에서 양식을 재구성하거나, DOCX를 중간 산출물로 만들어 업로드하지 않는다.
- Google Drive/Docs 쓰기 연결과 네이티브 copy/edit 기능은 필수다. 기능이 없으면 다른 형식으로 우회하지 않는다.
- 기본 문서명: `[답변서]소비자기관_<contract_number>`
- 계약번호가 없으면 `[답변서]소비자기관_<YYYYMMDD>`
- 저장 위치는 사용자가 지정한 폴더를 우선하고, 지정이 없으면 현재 사건 자료가 있는 폴더 또는 `ChatGPT` 폴더를 사용한다.
- 결과는 **Google Docs 링크만** 반환한다. PDF와 메일 초안은 사용자가 별도로 요청하지 않으면 만들지 않는다.

## Google Docs 생성

1. 작성 전 `case-data.json`을 만들고 `scripts/validate_case_data.py case-data.json`을 실행할 수 있으면 실행한다. 실행 환경이 없더라도 같은 검증 규칙을 모델이 직접 적용한다.
2. [google-docs-template.md](references/google-docs-template.md)의 기준 Google Doc을 읽어 구조 지문과 SpaceV 로고 존재를 확인한다.
3. 기준 문서를 **네이티브 copy**로 복제한다. 원본은 절대 수정하지 않는다.
4. 복제본의 현재 문서 구조와 표 범위를 다시 읽는다.
5. 문서번호, 수신인, 제목, 계약기간, 이용상품, 2항 본문, 3항 본문, 발신일자/담당자 등 현재 사건 값만 필요한 범위에서 교체한다.
6. 계약기간과 이용상품은 `contract_source.raw_excerpt`에서 잠근 문자열을 그대로 넣는다.
7. 편집 후 문서를 다시 읽어 다음을 검증한다.
   - SpaceV 로고 `positionedObject`가 남아 있음
   - `1. 계약 내용`의 기본 표가 2행×2열이며 계약기간·이용상품만 존재
   - 계약기간/이용상품이 case data와 문자 그대로 일치
   - `2. 민원 내용 및 확인 결과`, `3. 민원 관련 당사 입장 및 조치`가 존재
   - `CS`, 불필요한 보증금, 불필요한 이용대금 세부 구성, `회신일 현재 ~ 확인되지` 문장이 없음
   - 템플릿 기준 사건의 오염 방지 서명이 하나도 남아 있지 않음
   - 불필요한 빈 문단/빈 페이지/중복 사실이 없음
8. 검증이 끝난 **네이티브 Google Docs URL만** 사용자에게 전달한다.

**중요:** 네이티브 copy 기능이 없거나 로고/양식을 보존할 수 없으면 새 문서를 임의로 다시 만들지 않는다. 양식 보존 실패는 완료가 아니다.

## 호출 예시

- `공문, 결제 상세, 계약메모 줄게. 소비자원 답변서 작성해줘.`
- `소보원 답변서 써줘. 필요한 건 먼저 물어봐줘.`
- `1372 회신 작성해줘. 이 건은 청소 관련 내용은 약하게 써줘.`
- `파일 필요 없고 채팅으로만 답변서 써줘.`
